## Notes per dimension

### 1. Cross-doc consistency

**What's coherent (worth saying):** the D6 ↔ api-notes ↔ transport.py triangle is fully aligned on the 7-operation surface (verified against `tests/test_transport.py`'s pinned `EXPECTED_METHODS`); the firmware story (v4.0.1, backup path, md5 `d0c76999…`, 1,015,808 B) is identical in AGENTS.md rule 4, README, firmware/README.md, and D-FL; the tiered telemetry cadence is identical in BRD §5 and arch §2.2; F2's stop→download→start order is correct in the BRD; Q1 is properly struck through and linked; safety rules are consistent everywhere.

**Drift clusters:**

- **The NUS misattribution (finding 3)** is the widest: it sits in the BRD, architecture (3 places), and two ADRs, while the two newest specs (api-notes, transport docstrings) state the correct channel. The ADR *substance* (JSON lines over stdout, D4) is untouched — only the physical-channel attribution is wrong — but it must not survive into #4/#5, where an agent debugging at GATT level (btmon/Wireshark, or reimplementing `download_user_program` per api-notes gotcha 6) would watch the wrong characteristic.
- **Install-while-running semantics (findings 4, 5):** AGENTS.md says install stops the running program; the GATT profile says install is *rejected* (BUSY) while a program runs; the BRD's flow implies the correct stop-first sequencing but never states the precondition. The newest spec (api-notes) omits it entirely. This is the single fact most likely to produce a subtly wrong state machine in #4.
- **Two state models (findings 6, 7):** BRD §5 and arch §4 disagree on state names, disconnect topology, and the chip vocabulary. Both diagrams are Mermaid, both look authoritative, and they were introduced in the same docs-restructure commit — drift by construction, not by decay.
- **Status-observability gap (finding 1):** the only internal contradiction *within* the newest spec layer itself. api-notes' design rationale ("the state machine consumes `status_observable` edges") and transport.py's docstring ("completion is observed through stdout/status subscriptions") both reference a subscription that the interface does not provide.

## Verdict

**The doc set is close but not ready to generate issues #4–#12 from.** It *is* ready to start #3 (with finding 12's checklist folded into the issue). The two blockers and the NUS family must be fixed first — all are one cheap docs-and-seam pass:

1. **Resolve program-end observability** (finding 1) — extend `Transport` with a status subscription, or explicitly scope PROGRAM transitions out of M1's machine. This is the only finding that touches code; everything else is docs.
2. **Rewrite architecture §4.5 in terms of Transport** (finding 2).
3. **Fix the NUS misattribution** across brd/arch/decisions (finding 3).
4. **Unify the two state models** into one canonical diagram (finding 6).
5. **Correct AGENTS.md's install-stops-program fact** and add the BUSY precondition to api-notes (findings 4, 5).
6. **Reconcile the scan-loop rule with the always-on service** (finding 8).

Findings 9–14 (README/archive framing, M1 row, mock mode, event-model ADR checklist, testing.md seam language, wrapper path) should ride along in the same pass; minors and nits can trail.

After that pass, every planned issue #4–#12 has a documented home, and #5 (the adapter) can be written almost verbatim from D6 + api-notes + transport.py — the strongest documentation in the repo today.
